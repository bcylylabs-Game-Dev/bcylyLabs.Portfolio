Connecting Components

UPFS components are deliberately modular. Upgrade SO remains the source of progression truth, while Economy, Currency, Info Provider and listeners add only the responsibilities your feature requires.

Component responsibilities

ComponentOwnsReferences
Upgrade SOStructure, values, completion and progression eventsNo supporting component required
Currency SOOne shared numeric balance and its persistenceIndependent data asset
Economy HandlerCosts, wallet policy, affordability and purchase transactionsUpgrade SO and Currency assets
Info ProviderPresentation-ready standard and custom metadataUpgrade SO
ListenersScene-level UnityEvent routingThe asset they observe
Important · Upgrade SO stays central

Supporting components read or extend progression behavior; they do not replace the Upgrade SO as the authoritative progression source.

Minimal progression setup

Use Upgrade SO alone when gameplay controls payment or unlock conditions elsewhere.

  1. 01
    Create Upgrade SO

    Author the complete Big and Small Upgrade sequence.

  2. 02
    Read current state

    Use GetCurrentUpgrade to initialize gameplay values.

  3. 03
    Advance

    Call PerformUpgrade after your own eligibility logic succeeds.

  4. 04
    React

    Subscribe to events or add an Upgrade Listener for presentation feedback.

Progression with an economy

Add Currency and Economy Handler when UPFS should evaluate affordability and execute payment.

  1. 01
    Create currencies

    Create one stable Currency SO for every supported payment balance.

  2. 02
    Connect source

    Assign the Upgrade SO to Upgrade Economy Handler and fetch its structure.

  3. 03
    Generate costs

    Configure matching currency names, ranges and distributions.

  4. 04
    Assign wallet

    Reference the Currency assets and select a payment mode.

  5. 05
    Purchase

    Use PurchaseNextUpgrade or PurchaseWithCurrency from the runtime UI.

Warning · Match Currency names

Economy cost definitions resolve Wallet entries by Currency Name. A spelling or casing mismatch prevents that Currency from satisfying the matching cost.

Presentation and UI setup

Add Info Provider when the interface needs more than level, value and price.

  • Use Upgrade SO for live current and next progression state.
  • Use Economy Handler for costs and affordability.
  • Use Info Provider for icons, labels, colors, materials and descriptions.
  • Use listener components for scene-configured refreshes and feedback.

Initialization order

  1. 01
    Load Currency and Upgrade state

    Restore authoritative player data first.

  2. 02
    Check synchronized structures

    Ensure Economy and Info Provider data reflect the current authored Upgrade structure.

  3. 03
    Bind listeners

    Enable subscriptions before the user can interact.

  4. 04
    Render UI

    Read current, next, cost and custom information into the first visible state.
