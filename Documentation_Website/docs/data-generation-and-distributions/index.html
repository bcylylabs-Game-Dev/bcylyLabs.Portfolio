Data Generation & Distributions

UPFS separates progression structure from curve shape. Generate the Big and Small Upgrade sequence first, then tune gameplay values, native prices and economy costs with distributions that fit the intended player experience.

Recommended generation order

  1. 01
    Define milestones

    Choose the number of Big Upgrades and Small Upgrades per group.

  2. 02
    Set gameplay ranges

    Choose starting and ending values for the progression.

  3. 03
    Set native price ranges

    Define the Upgrade SO price range when the native price is used.

  4. 04
    Generate Upgrade data

    Create and review the nested progression.

  5. 05
    Fetch dependents

    Refetch Economy Handler and Info Provider after the structure is stable.

  6. 06
    Distribute currency costs

    Generate each economy series independently and review the output.

Warning · Generate deliberately

Regeneration can replace previously authored values. Confirm the operation and keep source control or a backup when balancing production data.

How curve evaluation works

Each sequential Small Upgrade receives a normalized position from the beginning to the end of the complete progression.

The selected distribution transforms that normalized position before UPFS interpolates between the configured start and end values.

Integer configurations round the resulting values. Float configurations preserve decimal precision where supported.

Tip · Evaluate representative points

During balancing, compare the first, quarter, middle, three-quarter and final values instead of inspecting only the endpoints.

Combine independent curves

Gameplay growth and purchase cost do not need to use the same distribution.

Distribution API

Upgrade SO exposes methods for applying value and price distributions to its current data.

csharp
float value = upgrade.ApplyValueDistribution(
+    normalizedPosition, startValue, endValue
+);

int price = upgrade.ApplyPriceDistribution(
+    normalizedPosition, startPrice, endPrice
+);
Information · Prefer Editor-time balancing

Generate and review production curves before release. Runtime redistribution should be an intentional feature, not a substitute for authored balance data.
